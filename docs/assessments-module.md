# Assessments module

Assessments is an independent module at `/assessments`, with its own sidebar group and module navigation.

Online CBT has its own route at `/assessments/online-cbt`, accessible from the module navigation, sidebar and existing exam actions. An optional positive `assessmentId` search parameter carries a selected editable self-assessment; the server still validates ownership and status. Opening the route only loads instructions and exam details. The explicit Start/Resume action starts or resumes the staff member's own exam, preserving the monthly limit. The exam, result scorecard and certificate link render in the page; only submission confirmation remains a dialog. Navigation away from an active exam asks for confirmation, waits for queued answer saves, and warns that the original deadline continues. Refreshing or returning allows the existing attempt to resume. Personal exam history remains on Assessments home.

- Normal staff see their own assessment history, current self-assessment and latest 50 online CBT attempts. History has server pagination and a status filter. A past assessment opens the existing workspace with its existing access and workflow rules.
- HR/Admin retain the existing management workspace on the home route. Questions are managed at `/assessments/question-bank`; configuration is consolidated at `/assessments/settings`.
- Department incharges and nursing supervisors see personal history at home and retain their review workspace at `/assessments/skill-assessments`.
- The former HR URLs redirect into Assessments, preserving bookmarks. The API paths and stored records are unchanged.

Assessment history calls the existing list API with `tab=my`. CBT history also explicitly supplies the current staff ID so a supervisor's home does not show all staff attempts. Existing server authorization remains authoritative. Module restrictions and missing staff profiles have explanatory states; failed requests offer Retry rather than appearing as empty history.

Self-assessment theory is read-only and derived exclusively from finalized CBT results, including a valid zero. All finalized CBTs for the staff member started within the assessment start/end dates (inclusive India calendar dates) contribute equally, whether standalone or linked. Missing assessment dates fall back to the cycle dates; undated legacy assessments use their linked attempts. Without a result, theory shows Pending CBT, practical ratings can be saved as a draft, and final submission is rejected. The server discards candidate-entered theory values. Incharge and nursing-supervisor theory/viva ratings remain independent evaluator scores.

Shared UI lives in `src/components/assessments/`. Frontend routes are thin wrappers under `src/routes/_authenticated/assessments/`; `src/routeTree.gen.ts` is generated by the existing TanStack Vite plugin.

Assessment Settings is available only to Admin and exact HR roles (including the existing linked staff HR role). It contains staff module access, assessment periods/cycles, CBT title/count/duration/timers/pass threshold/difficulty mix/department mix, and competency domain/objective/scenario/rubric management. The staff-access toggle has moved from Hospital Settings and uses the existing persisted hospital flag through narrowly validated GET/PUT `/skill-assessment/settings` endpoints. HR can change this flag without access to other hospital settings. HR/Admin retain settings access while normal staff access is disabled.

The assessment workspace keeps a read-only rubric explorer; period and rubric editing now belong to Settings. The question bank keeps question CRUD while CBT configuration belongs to Settings. Server guards reject settings writes from department incharges, nursing supervisors, management approvers and ordinary staff, including direct criterion, domain, cycle and CBT-config requests. Read-only catalogs, exam configuration needed by candidates, and existing assessment review permissions remain available as before.

Staff can use **Print certificate** on finalized CBT history rows or the post-exam scorecard. `/assessments/certificates/:attemptId` displays a printable A4 result certificate with hospital branding, employee identity, the exam-time department, completion date in India time, saved score and benchmark, result and a stable reference. The Print / Save as PDF action uses the browser print dialog. Passed results have an achievement title; results below the benchmark are identified as result certificates without claiming success. Timed-out attempts show that saved answers were graded.

The certificate endpoint `/api/skill-assessment/exam/attempts/:attemptId/certificate` permits only the candidate or HR/Admin. It rejects unfinished attempts and missing final result data, reads saved results without regrading or using the current exam configuration, and excludes all question snapshots/answer keys. No exam or assessment state is changed by viewing or printing a certificate. The HR/Admin-only NABH form print button remains separate.

The bottom QR barcode embeds the entire certificate response as UTF-8 JSON, with `schema: acme.cbt-certificate.v1`: hospital name/address, employee name/code/department, reference, exam identifier/date/status, score, passing benchmark, outcome, question counts and rating. It contains the details directly rather than a lookup URL and is generated locally. Vector black modules on a white background and a four-module quiet zone preserve print clarity. The QR data records the displayed result; it is not a cryptographic signature.

CBT exams are limited to one new attempt per staff member per calendar month in India time (Asia/Kolkata), across all linked assessments and standalone exams. Starting an exam uses the monthly allowance regardless of its later outcome. Any existing in-progress attempt resumes instead of creating another; an expired session resumes with zero time so its saved answers can be graded. The start endpoint checks the month under the existing per-staff transaction advisory lock and returns HTTP 429 with `code: CBT_MONTHLY_LIMIT` and `nextEligibleAt` when blocked. The next allowance starts at midnight on the first of the following month. Existing history is retained, including older duplicate monthly attempts.

CBT theory is calculated separately per domain: correct answers divided by all questions in that domain, multiplied by 5 and rounded to one decimal. Unanswered questions count in the denominator. Each self-assessment objective receives its own domain rating from the saved exam snapshot and answers. A domain absent from the exam remains null and displays Not assessed in CBT; staff can still submit complete practical ratings after completing CBT. The overall assessment theory summary averages the saved overall ratings of all eligible exams. Each domain averages its per-exam ratings, including zero, only across exams containing that domain. This is an equal-exam arithmetic mean rounded to two decimals. The monthly exam-start limit remains unchanged. Finalized assessments retain their saved historical scores. The post-exam scorecard includes domain results.
